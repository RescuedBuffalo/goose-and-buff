# Telemetry events — schema

Local-only run-event log. One newline-delimited JSON file per run at
`user://telemetry/<run_id>.jsonl`. Foundation for later AI-adaptive
content (difficulty scaling, suggested unlocks). No external endpoint
in M2.

## Architecture

- **Logic**: [`scripts/logic/telemetry.gd`](../scripts/logic/telemetry.gd) — pure `RefCounted`. Emits an `event_logged` signal for every `Telemetry.log(kind, payload)` call. No I/O, no scene-tree references.
- **Adapter**: [`scripts/adapters/telemetry_io.gd`](../scripts/adapters/telemetry_io.gd) — listens on `event_logged`, buffers events under a mutex, drains to disk on a worker thread (woken by a periodic 2 s tick from `_process` and immediately on `run_end`). The hot path is mutex-guarded buffer append only — no synchronous file I/O at the call site.
- **Wiring**: [`scripts/adapters/main.gd`](../scripts/adapters/main.gd) constructs the `Telemetry` instance, attaches the `TelemetryIO` adapter, and calls `Telemetry.log(...)` from the appropriate signal handlers.

## Privacy

- `run_id` is a per-run nonce (`<unix_seconds>-<16-bit random>`). It is **not** a device or user identifier and is regenerated on every `start_run`.
- No IP, no machine ID, no OS info, no account info.
- Payloads only carry run-scoped gameplay data: enemy types, item ids, tile coordinates, hp values. Audit any new payload field before merging.
- Log files stay local. If a server endpoint is added later, it must ship with an opt-in setting.

## Envelope

Every event is a single JSON object on its own line:

```json
{
  "ts": 1746468023.412,
  "run_id": "1746468023-3a9c",
  "kind": "run_start",
  "payload": { ... }
}
```

| Field | Type | Notes |
| --- | --- | --- |
| `ts` | `float` | Unix seconds (system clock) at the moment the event was logged. |
| `run_id` | `string` | Nonce generated by `Telemetry.start_run()`. Same value across all events in the run. |
| `kind` | `string` | Event kind — one of the values below. |
| `payload` | `object` | Kind-specific fields; see below. |

## Event kinds

### `run_start`

Fires once per run, immediately after the run is reset and the starter
inventory is granted.

| Payload field | Type | Notes |
| --- | --- | --- |
| `hero_id` | `string` | e.g. `"Buffalo"`. |
| `max_nights` | `int` | Survival win condition (currently 3, from `data/day_night.gd`). |
| `deck_composition` | `array` | Starter loadout entries `[{id, count}, ...]`. Cards are dormant in the survival rebuild (BUF-136), so this currently logs the seed inventory from `STARTER_ITEMS`; once cards return it will also include the chosen deck (BUF-115). |
| `seed` | `int` | Procgen seed for this run's world (BUF-145). Same `(seed, day_index, hero_id)` reproduces the same WorldDef — analytics can re-roll a flagged run offline. |
| `seed_string` | `string` | 8-char lowercase hex of the unsigned 32-bit seed — the share-friendly form the run-end Copy button hands the player. |
| `owned_upgrades` | `array` | Lodge upgrade ids active for this run (BUF-147). Empty on a fresh save. |

### `run_end`

Fires on victory (cycle complete) or defeat (hero or lodge core down).
Always the final event in a run file. The wiring layer enforces this
by deferring both `_run_defeat` and `_run_victory` via `call_deferred`,
so any signal raised earlier in the same frame (the fatal hit's
`hero_damage_taken` from the enemy adapter, or a `resource_gathered`
emitted later in `_process` after `day_night.tick` triggered cycle
completion) lands in the buffer before `run_end`. `_unhandled_input`
is also phase-gated so clicks on the end-screen scrim can't trigger
trailing `ability_cast` events from later frames.

| Payload field | Type | Notes |
| --- | --- | --- |
| `outcome` | `string` | `"victory"` or `"defeat"`. |
| `nights_survived` | `int` | Number of dawn transitions completed. |
| `resources_gathered` | `int` | Total items added to inventory via gathering during the run. |
| `enemies_felled` | `int` | Enemies killed by the hero (does not count enemies that reached the core). |

### `wave_start`

Fires when night begins (dusk → night transition triggers
`WaveDirector.start_wave`).

| Payload field | Type | Notes |
| --- | --- | --- |
| `round_index` | `int` | Day index, 1-based. |
| `archetype` | `string` | ALL-CAPS archetype id (e.g. `"PROBE"`, `"RUSH"`, `"SKIRMISH"`, `"SIEGE"`). Empty string if absent. |
| `has_mini_boss` | `bool` | True on the SIEGE night (AlphaWolf). |
| `composition` | `object` | `{ enemy_type: count }` summary of the wave roster. |

### `wave_end`

Fires when night ends (night → dawn transition triggers
`WaveDirector.end_wave`).

| Payload field | Type | Notes |
| --- | --- | --- |
| `round_index` | `int` | Same index that started the wave. |
| `nights_survived` | `int` | Cumulative count after this wave. |

### `hero_damage_taken`

Fires when an enemy adapter's `damaged_target` signal hits the hero.

| Payload field | Type | Notes |
| --- | --- | --- |
| `amount` | `float` | Damage actually applied (post-clamp at HP 0). On a fatal hit this is less than the attacker's nominal attack value. |
| `hp_after` | `float` | Hero HP after the hit. |
| `hp_max` | `float` | Hero max HP (snapshot). |
| `source_enemy_type` | `string` | Enemy archetype that landed the hit (e.g. `"FrostWolf"`). |

### `hero_killed_enemy`

Fires when an enemy's `died` signal fires (only happens on hero kill —
core-reached enemies are queue-freed without emitting `died`).

| Payload field | Type | Notes |
| --- | --- | --- |
| `enemy_type` | `string` | Enemy archetype that was killed. |

### `resource_gathered`

Fires when a gather completes successfully.

| Payload field | Type | Notes |
| --- | --- | --- |
| `resource_kind` | `string` | Resource node kind (e.g. `"tree_pine"`, `"rock_field"`, `"berry_bush"`). |
| `yields` | `object` | `{ item_id: count }` rolled by `Resources.roll_yield`. |

### `building_placed`

Fires when `BuildSystem.place` succeeds and the placeable is committed.

| Payload field | Type | Notes |
| --- | --- | --- |
| `item_id` | `string` | Inventory item that was consumed (e.g. `"wood_wall"`). |
| `placeable_id` | `string` | The resulting placeable archetype. |
| `tile_x` | `int` | Tile coordinate. |
| `tile_y` | `int` | Tile coordinate. |

### `ability_cast`

Fires on a successful weapon swing (the M2 prototype's only
ability-style action). When signature abilities land, additional
`ability_id` values will join here.

| Payload field | Type | Notes |
| --- | --- | --- |
| `ability_id` | `string` | Currently always `"weapon_swing"`. |
| `weapon_id` | `string` | Equipped weapon at swing time (e.g. `"hand_axe"`, `"bare_hands"`). |
| `hits` | `int` | Number of enemies caught in the swing arc. |

### `ember_earned`

Fires once per run, just before `run_end`, after the run lifecycle has
computed the ember award and persisted it via `SaveIo.add_embers`. The
event lives inside the run's JSONL file (sharing the run's `run_id`)
so analytics can join earn-rate to the same outcome / hero / seed
context already on `run_start` / `run_end`.

| Payload field | Type | Notes |
| --- | --- | --- |
| `outcome` | `string` | `"victory"` or `"defeat"`. |
| `amount` | `int` | Embers awarded for this run (the same value the end screen displays). |
| `nights_survived` | `int` | Mirrors the `run_end` field for ease of joining. |
| `resources_gathered` | `int` | Mirrors `run_end`. |
| `enemies_felled` | `int` | Mirrors `run_end`. |
| `hero_id` | `string` | Active hero at run-end. |
| `artifact_id` | `string` | Lodge artifact left behind (BUF-130). |
| `artifact_is_new` | `bool` | True if the artifact was a first-time discovery — the trigger for the per-discovery ember bonus (BUF-149). |
| `first_hero_run` | `bool` | True if this was the player's first ever run with `hero_id` — the trigger for the "try them out" ember bonus (BUF-149). |

### `ember_spent`

Fires when the player buys a lodge upgrade (BUF-148 tree). Spends
happen between runs, outside any active `run_id`, so this event lives
in a separate JSONL stream — `user://telemetry/lodge_events.jsonl` —
rather than the per-run files. The envelope (`ts` / `kind` /
`payload`) matches; `run_id` is omitted because no run is active at
spend time.

| Payload field | Type | Notes |
| --- | --- | --- |
| `upgrade_id` | `string` | The upgrade purchased (key into `data/upgrades.gd`). |
| `amount` | `int` | Embers debited (= the upgrade's `cost`). |
| `hero_scope` | `string` | `"Buffalo"` / `"Goose"` / `"Fox"` / `"Shared"` — useful for slicing spends by tab. |
| `tier` | `int` | Tree depth (1–3). |
| `balance_after` | `int` | Embers remaining after the spend. |

## File location

Files are written to Godot's `user://` directory:

- Windows: `%APPDATA%\Godot\app_userdata\The Long Watch — Survival Prototype\telemetry\<run_id>.jsonl`
- macOS: `~/Library/Application Support/Godot/app_userdata/.../telemetry/<run_id>.jsonl`
- Linux: `~/.local/share/godot/app_userdata/.../telemetry/<run_id>.jsonl`

Files accumulate forever in M2 — there is no rotation. Manual delete
is fine.
