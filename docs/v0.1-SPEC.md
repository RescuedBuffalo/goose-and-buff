# v0.1 — Retrospective

> This file documented the *forward-looking* v0.1 contract back when the project lived in Roblox. After the Godot pivot, v0.1 is what shipped in the prototype rather than a target — so this file becomes a retrospective. Forward-looking work lives in [Linear](https://linear.app/buffalo-studios/project/buffalo-and-goose-593efd9062a8) under M1 (Solo loop complete).

## What v0.1 is

A single-player vertical slice in Godot. Buffalo only. One sector. 5-card hand. One signature ability (Charge). One enemy archetype (GruntMelee). Three escalating waves. Win/loss state. Click-to-restart.

The point was answering three questions cleanly:

1. **Does the illustrated 2D art direction work in Godot?** Half-yes — palette and composition land, but real illustrations are still placeholder. Worth committing one illustrated card before the pivot decision was made fully irreversible (we'd already committed by the time PROTOTYPE-NOTES landed).
2. **Does the card mechanic feel good?** Yes. The drag-drop loop is clean enough that the team committed to it as the core gameplay primitive — units, buildings, abilities, resources are all card-shaped going forward.
3. **Is Godot's workflow sustainable?** Yes. The architectural discipline carried over (pure logic / adapter / data), the MCP integration is good for live iteration, the engine matches the art direction without a fight.

## What ships in v0.1

Per the prototype's `PROTOTYPE-NOTES.md`:

- Buffalo character on screen, WASD-controlled, totem PNG sprite (with flat-circle fallback for first-open before imports complete).
- Buffalo sector floor + core in canonical Buffalo palette, sourced from `data/sectors.gd` (which mirrors the original `Sectors.lua`).
- 5-card hand at the bottom; cards render with faction palette, totem dot, cost pip, name, description, flavor.
- Drag-drop unit cards spawn Calf / Ostrich / Longhorn at the drop position. Drag-drop building card places (or upgrades) the Production Node. Stockpile resource card auto-pays. Charge ability card casts during wave from Buffalo toward the drop point.
- Wave timer ticks during prep (30s default). Eight grunts per wave spawn off the right edge and walk left toward the core. Units engage on sight.
- Round outcomes: 3 cleared waves → "Run complete." / "We held."; core HP 0 → "Run ended." / "The line broke." Single-button restart.
- HUD: Buffalo HP, Core HP, coin balance, phase + round, timer, wave banner. All values use design tokens; no hardcoded colors anywhere outside `scripts/autoload/design_tokens.gd`.

## What's stubbed or deviated

- **No multiplayer.** Per spec — multiplayer is M4.
- **Totem PNG, not SVG, for Buffalo.** The design bundle ships only `buffalo.png` for Buffalo (others are SVG). We kept it as shipped instead of regenerating.
- **Hero takes no damage.** Enemies target deployed units or the core, never the hero. `Hero.damage()` is plumbed but unused — wired up in M1 (BUF-109).
- **Adapters consolidated.** The original spec listed separate `wave_spawner.gd`, `unit_spawner.gd`, `ui_renderer.gd`; all folded into `scripts/adapters/main.gd` because the wiring is small. Pure-logic / adapter / data split is preserved — the rule that matters.
- **Fonts are Godot's fallback.** Real fonts (Young Serif, Nunito, JetBrains Mono) come in M3 (BUF-121).
- **No animations** beyond a single tween on the Charge AoE. Static sprites otherwise. M3 (BUF-119) handles the animation pass.
- **No sound.** M3 (BUF-120).

## Architecture preserved across the pivot

The Roblox v0.1 spec defined a load-bearing layer split: pure logic / Roblox-aware adapters / pure data. The Godot prototype kept this discipline:

- `scripts/logic/wave_director.gd`, `ability_resolver.gd`, `card_system.gd`, `economy.gd` — zero scene-tree references. Port to any engine in an afternoon.
- `scripts/adapters/main.gd` — every Godot API call lives here.
- `data/heroes.gd`, `units.gd`, `cards.gd`, `sectors.gd`, `waves.gd`, `enemies.gd` — plain dictionaries. The Roblox `.lua` files mapped over with mostly syntactic edits.

This is what made the engine pivot cheap. Hold the line on it.

## Open questions raised by the prototype

Captured here in case future planning loses them:

1. **The art direction question is half-answered.** Palette + composition is in place; real illustrations are placeholder. M3 closes this.
2. **The card mechanic prototype demonstrates the loop but doesn't prove strategy depth.** Three card types and one ability isn't enough to tell whether deckbuilding is interesting. M2 (expanded card pool, meta-progression) closes this.
3. **Architecture discipline carried cleanly.** The eventual portability claim held under real test.

## Where work goes from here

See [Linear](https://linear.app/buffalo-studios/project/buffalo-and-goose-593efd9062a8). Milestones in order:

- **M1 — Solo loop complete (all 3 heroes).** Goose deck, Fox deck, hero select, three enemy archetypes, hero damage. The bar is "I can sit down for 5 minutes, pick a hero, play one full run, and feel something."
- **M2 — Solo depth + 30-minute session.** Save/load, lodge hub, card unlocks, wave variety, difficulty curve. The bar is "I want one more run."
- **M3 — Visual polish + audio.** Real illustrations, animations, sound, fonts. The bar is "this looks like the game I imagined."
- **M4 — Multiplayer co-op.** Networking, lobby, sequential info-asymmetric waves, cross-sector help abilities. The original spine mechanic comes back.
